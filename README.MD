🛠️⚡ Бэкенд для AI-ассистента MCBuddy — агент на [Mastra](https://mastra.ai) поверх OpenRouter, который отвечает игрокам в Minecraft и в Telegram. В игре он видит, что происходит с игроком: инвентарь, здоровье, что вокруг, рецепты этого сервера. Свежие факты он ищет в интернете сам, когда это нужно.

## Как это работает

Плагин открывает один потоковый запрос `POST /api/v2/chat` на каждый вопрос. Сервер отвечает событиями Server-Sent Events, пока агент работает:

- `reasoning` — кусочки рассуждений модели, если она их отдаёт;
- `tool_call` — агенту нужно что-то из игры, например инвентарь. Плагин выполняет инструмент у себя и присылает результат на `POST /api/v2/chat/{run_id}/tools/{call_id}`;
- `tool_status` — что агент делает сейчас: смотрит инвентарь, ищет в интернете;
- `text` — ответ по мере генерации, затем `usage` и `done`.

Для `/askx` вместо текста приходит событие `commands` со списком команд. Полное описание протокола — в [docs/protocol-v2.md](docs/protocol-v2.md).

Инструменты игры видят только спросившего игрока и мир вокруг него: чужие координаты и инвентари агенту недоступны. Список инструментов присылает плагин, и администратор сервера может отключить любой. Кроме чтения, есть безобидные действия для всех: стрелка компаса к точке, сортировка инвентаря, напоминания и блокнот. В блокнот агент записывает заметку, привязанную к месту («тут житель продаёт стрелы»), а потом находит её по вольному вопросу и ведёт туда. Ещё агент заглядывает в сундуки, считает прочность, опыт и еду, подсказывает, куда ставить факелы, и прикидывает выход фермы. Инструменты, которые выдают предметы, телепортируют или меняют режим игры, время и погоду, получают только операторы. Бэкенд отбрасывает их для остальных, даже если плагин их прислал.

На бэкенде работают три инструмента:

- `search_web` ищет в интернете через поисковую модель. Агент сам решает, когда искать, а не ищет на каждый вопрос;
- `exact_calculations` точно считает выражения через [math.js](https://mathjs.org) с 64 значащими цифрами: стаки, координаты Незера, опыт, перевод единиц. Каждое выражение считается в отдельном воркере не дольше секунды;
- `remember` и `forget` ведут долгую память об игроке.

Агент отвечает на языке вопроса. Локаль игры нужна, только когда язык по сообщению не понять.

### Память

У каждого игрока есть сессия и долгая память. Сессия хранится в Redis 24 часа после последнего вопроса. В ней от 8 до 12 последних вопросов дословно и краткое резюме всего, что было раньше. Резюме пишет модель после ответа, поэтому игрок его не ждёт. Запросы `/askx` попадают в сессию одной строкой: что попросили и какие команды получились.

Долгая память лежит в MongoDB и не истекает. Это до 30 коротких фактов: где база, над чем игрок работает, как ему удобнее отвечать. Агент записывает их сам и говорит об этом. Плагин даёт игроку `/ask new`, `/ask memory` и `/ask forget` через эндпоинты `/api/v2/users/{user_id}/…`, описанные в протоколе.

Старые `POST /api/ask` и `POST /api/askx` работают как раньше. Их используют Telegram-бот и плагины до 2.0: тот же агент, но без инструментов игры, ответ одним JSON. Сессия общая для обеих версий API.

> Ожидание результатов инструментов живёт в памяти процесса, поэтому сервер рассчитан на один экземпляр. Если запускать несколько, запрос с результатом должен попадать на тот же экземпляр, что держит поток.

## Сборка и деплой

### Docker Compose (рекомендуется для продакшена)

1. **Подготовка конфигурации:**
   ```bash
   # Клонируйте репозиторий
   git clone https://github.com/mcbuddy-ai/mcbuddy-server
   cd mcbuddy-server
   
   # Скопируйте пример переменных окружения
   cp .env.sample .env
   
   # Отредактируйте .env файл с вашими настройками
   nano .env
   ```

2. **Настройка домена:**
   ```bash
   # Отредактируйте Caddyfile и замените mcbuddy.ru на ваш домен
   nano configurations/caddy/Caddyfile
   ```

3. **Запуск:**
   ```bash
   docker compose up -d
   ```

4. **Проверьте статус:**
   ```bash
   docker compose logs -f mcbuddy-server
   ```

### Docker Compose с готовым образом

Если хотите использовать готовый образ и управлять MongoDB/Redis самостоятельно:

1. Задекларируйте сервис mcbuddy-server в `docker-compose.yml`:

```yaml
services:
  mcbuddy-server:
    image: ghcr.io/mcbuddy-ai/mcbuddy-server:1.3.3
    env_file: .env
    environment:
      MONGODB_URI: ${MONGODB_URI}
      REDIS_URL: ${REDIS_URL}
      OPENROUTER_API_KEY: ${OPENROUTER_API_KEY}
      # ... другие переменные окружения
```

> **Примечание**: Вам потребуется передать все переменные окружения из файла `.env` или любым другим удобным способом.

2. Задекларируйте сервисы MongoDB и Redis в `docker-compose.yml`. 
> Важно, версия **MongoDB** должна быть `5.0+`, а **Redis** должна быть `6.0+`.

3. Запустите сервисы:
```bash
docker compose up -d
```

### Bare Metal

1. **Установка зависимостей:**
   ```bash
   # Установите Bun.js
   curl -fsSL https://bun.sh/install | bash
   
   # Установите пакеты
   bun install
   ```
> Важно! Не забудьте развернуть зависимые сервисы: Redis, MongoDB и Caddy при надобности.

2. **Настройка переменных окружения:**
   ```bash
   cp .env.sample .env
   # Отредактируйте .env с настройками для MongoDB, Redis и OpenRouter
   ```

3. **Запуск:**
   ```bash
   # Разработка
   bun run dev
   
   # Продакшен
   bun run build
   bun run start

   # Проверки
   bun run typecheck
   bun test
   ```

**⚠️ Важно:** Обязательно настройте переменные окружения из файла `.env.sample` перед запуском. Особое внимание уделите `OPENROUTER_API_KEY`, `MONGODB_URI` и `REDIS_URL` и промптам.

## Переменные окружения

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | Ключ OpenRouter | обязательна |
| `OPENROUTER_API_URL` | Адрес API OpenRouter | `https://openrouter.ai/api/v1` |
| `OPENROUTER_API_MODEL` | Модель агента. Нужна модель с вызовом инструментов: `perplexity/sonar*` не подойдёт | `openai/gpt-6-luna` |
| `SEARCH_MODEL` | Модель для веб-поиска, с доступом в интернет | `perplexity/sonar` |
| `OPENROUTER_API_CTX` | Объём контекста поиска: `low`, `medium`, `high` | `medium` |
| `OPENROUTER_REASONING_EFFORT` | Усилие рассуждений для моделей, которые умеют рассуждать: `low`, `medium`, `high` | не задано |
| `TOOL_TIMEOUT_MS` | Сколько ждать ответа плагина на вызов инструмента | `15000` |
| `MAX_AGENT_STEPS` | Сколько шагов (вызовов модели) агент делает за один вопрос | `8` |
| `MAX_ACTIVE_RUNS` | Сколько потоковых вопросов обрабатывается одновременно | `200` |
| `SSE_PING_MS` | Как часто слать пинг в поток, чтобы прокси не рвали соединение | `15000` |
| `CHAT_TTL_SECONDS` | Сколько живёт сессия чата после последнего вопроса | `86400` |
| `CALC_TIMEOUT_MS` | Сколько `exact_calculations` даёт одному выражению | `1000` |

### Промпты

Промпты лежат в [src/prompts](src/prompts): `minecraft-ask.md`, `minecraft-askx.md` и `telegram.md`. Bun встраивает их в сборку. К промпту добавляется блок о текущем разговоре: игрок, локаль, версия сервера, доступные инструменты, резюме сессии и память об игроке.

Старые переменные `SYSTEM_MESSAGE*` больше не читаются: промпты меняются только в `src/prompts`. Если основной моделью указана Perplexity (`perplexity/…`), она не умеет вызывать инструменты, поэтому сервер сам переносит её в поиск, а отвечает моделью по умолчанию.

## Рантайм конфигурация

У пользователей бэкэнда есть возможность переопределить токен от openrouter.ai на свой, чтобы мониторить свои траты и иметь свои правила для роутинга AI моделей. 

Для этого достаточно в запросах на этот бэкэнд отправить заголовок `X-OpenRouter-Token: sk-xxxx-xxxx`

Это позволит вам использовать свой биллинг и тарификацию.

## Стек

- **TypeScript** — основной язык разработки
- **Bun.js** — быстрый JS runtime и пакетный менеджер
- **Mastra** — агент, инструменты и стриминг поверх AI SDK
- **AI SDK + @openrouter/ai-sdk-provider** — доступ к моделям OpenRouter
- **zod** — схемы запросов и инструментов
- **MongoDB** — основная база данных для пользователей и метрики
- **Redis** — кэширование и хранение истории чата
- **Docker & Docker Compose** — контейнеризация и оркестрация
- **Caddy** — реверс-прокси и SSL-терминация
- **OpenRouter** — API для доступа к различным AI моделям
- **Mongoose** — ODM для MongoDB
- **BullMQ** — система очередей и фоновых задач
- **tslog** — структурированное логирование (которое я благополучно не использую *trollface.png*)
